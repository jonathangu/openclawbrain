Local memory authority for AI agents

Give your agents memory with judgment.

OpenClawBrain helps local AI agents remember the durable things that matter without blindly obeying old context.

Generic memory retrieves old notes. OpenClawBrain governs memory as evidence: what was said, where it applies, whether it is stale, what superseded it, what should be forgotten, and why a memory was used or withheld.

The difference: relevance is not authority. A memory can match the turn and still be too old, too broad, private, superseded, or unsafe to inject.

What it does

Remembers durable lessons

Corrections, preferences, workflows, project facts, and operating rules become scoped memories, not raw transcript dumps.

Uses memory with judgment

Memory Authority checks whether a memory is current, scoped, safe, non-superseded, and compatible with the current instruction.

Maintains the graph

Graph Maintenance proposes duplicate cleanup, bad edge retirement, stale-memory review, scoped exceptions, and tombstone-safe forgetting.

Bridges Codex from Telegram

Ask your OpenClaw agent what Codex UI is doing, watch a goal finish, or get a clean handoff without turning Telegram into a noisy coding UI.

Leaves local proof

Status, proof, graph, search, route decisions, proposals, lineage, and edge observations make memory inspectable.

One memory loop

You correct the agent: “Actually, use pnpm in this repo.”

OpenClawBrain distills that into a scoped correction. Later, when you say “Run the tests,” SQLite FTS retrieves the correction, ContextSelector ranks it, and the prompt receives a bounded block:

<openclawbrain_context>
Relevant memory:
- Must follow: Use pnpm in this repo.
</openclawbrain_context>

The agent runs pnpm test without you re-teaching the convention. Afterward, OpenClawBrain records whether the memory helped, failed, was ignored, or got corrected. Later, graph maintenance can consolidate duplicates or flag stale high-authority tool memories for review.

Codex on your computer, OpenClaw in your pocket

Jonathan's current workflow uses Codex UI as the high-bandwidth coding workbench at the computer, and OpenClaw/Telegram as the mobile operator surface. OpenClawBrain sits between them as the continuity layer.

/brain codex status
/brain codex threads
/brain codex watch --latest
/brain codex handoff

That lets you ask from your phone: what is Codex working on, did it finish, is it blocked, what changed, and what should I check when I get back to the machine?

Memory graph maintenance

OpenClawBrain does not just remember more. It maintains what it remembers.

/brain graph health
/brain graph dry-run
/brain graph proposals
/brain graph explain <proposalId>
/brain graph apply <proposalId>

Safe automatic changes are intentionally narrow: exact duplicates, bad edges, and observation-only feedback. Semantic merges, scoped exceptions, privacy changes, and stale high-authority changes stay review-gated.

Install in a minute

openclaw plugins install clawhub:openclawbrain
openclaw plugins enable openclawbrain
openclaw gateway restart

Multiple agents/profiles are supported through scopes.agents; each agent gets its own local activation root and memory graph.
