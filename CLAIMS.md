# Claims boundary

Last updated: 2026-04-24

This file defines what OpenClawBrain claims to do today. The product agenda is selective intervention, but only bounded surfaces are claimed until they are frozen with proof. Unique wins, ties, and guardrail keeps are reported separately on purpose.

## Claimed

- The public operator front door is `openclawbrain install --openclaw-home <path>` pinned to one OpenClaw home.
- Install, attach, status, proof capture, rollback, detach, and uninstall work on real OpenClaw profiles on the exercised macOS host surface.
- The runtime serves only promoted packs, records explicit skip modes, and fails open if it cannot safely compile brain context.
- The learning pipeline exports turns, builds candidate packs off the response path, and only serves promoted packs.
- Explicit user corrections can be stored durably and retrieved on bounded current-relevant routes.
- Dedicated-brain separation across two real profiles is proven.
- The detailed status and proof surfaces report runtime/load truth, current promoted-pack metadata, and machine-readable operator state for one selected home.
- Bounded activation-first scorecards exist and distinguish unique wins, ties, restraint counts, and broad-live guardrail regressions on checked bundles.

## Not yet claimed

- A frozen later-preference current-choice fidelity lane on the real runtime path
- A frozen specificity / must-not-fire lane beyond the current activation-first scorecards
- Tool-capability choice as a public proof headline
- Same-gateway multi-profile attachment as a general public lane
- Shared-root concurrent write safety
- Broad cross-platform support beyond the macOS hosts exercised so far
- Automatic gateway lifecycle management or service orchestration
- Manual slot rewriting, LaunchAgent editing, or environment-file management as supported operator flows
- `--proof` as a shipped install flag on every operator surface
- Universal dated citations on every recalled-memory surface
- Exact evidence-backed attribution on every learning and supervision path
- Broad live answer-quality gains or "general smarter memory" claims beyond the current bounded proof surfaces

## How to extend this boundary

- Update this file when a release turns an unclaimed item into a claimed one.
- Link the supporting release in [CHANGELOG.md](CHANGELOG.md), the relevant release note, or a frozen evidence bundle.
- For decision-quality claims, report unique wins, ties, regressions, and keep-clean negatives separately.
- If a change weakens a claimed behavior, call it out in the changelog and contributor docs before release.
